# AI4Instruments

### 让仪器成为可编程、可理解、可持续发展的科学研究伙伴

**AI 设计与实现 + AI 开发和使用。**

作者：**Shuxing Yang** · [English](README.md) · [PDF 论文](paper/AI4Instruments.pdf) · [HTML 论文](paper/AI4Instruments.html)

## 为什么需要 AI4Instruments

实验能力不仅取决于研究者提出什么问题，也取决于仪器允许什么操作、提供什么观察，以及这些能力能否被重新组合和继续开发。

来自不同厂商和实验室的设备，在机械结构、电路、控制器、驱动、接口、时钟和数据格式上存在差异。许多实际能力被限制在图形界面或预设流程中，许多关键状态依靠人的经验判断。这些缺口既消耗人类研究者的时间，也限制 AI 持续开展真实实验。

**Instruments4AI** 从现有仪器出发：建立电控和编程接口，准备手册与 SDK，组织工具与知识，跑通串并行实验，再针对课题编写工作流。

**AI4Instruments** 将视野延伸到仪器本身：从立项、设计、制造、软硬件协同开发，到实际使用、测量表征与下一轮改进，让 AI 持续参与。两者可以衔接；已有实验平台是起点，实验中发现的问题推动下一代仪器的发展。

## 三层操作体系

| 层级 | 定义 | 示例 |
| --- | --- | --- |
| **Basic Operations** | 在明确的硬件抽象层级上，最基础的控制与观察操作 | 设置曝光、读取位置、配置触发、采集信号 |
| **Standard Operations** | 基于基础操作构成的可复用实验过程 | 一次成像、液体转移、温度程序、薄膜沉积 |
| **Workflow Operations** | 跨设备、跨样本、包含串行、并行与反馈的实验组织 | 合成—加工—表征—分析—下一轮设计 |

基础目标是 **a complete set of basic operations**。这里的完备性对应明确的能力清单：可调量、可观测量、模式、状态变化和时序关系。清单需要追溯到硬件与实际测量；未开放的能力应当作为缺口记录。

操作的语义应清晰、尽量不重复，但这不等于不同操作在物理执行中永远没有资源冲突。一次命令被接受，也不等于相应物理过程已经完成；读回、稳定时间和完成条件需要明确。

## 从底层能力到新的科学实验

编程连接控制器、执行器与传感器。理解电路、芯片、固件和硬件执行模型，使 AI 有机会开发高层应用尚未暴露的能力。机械、材料、几何、热过程和样本条件同样决定实验效果，需要与软件描述相互对应。

高层操作应能向下追溯其实现。遇到新问题时，可以复用已有过程，也可以修改、重组或建立新的过程。需要精确时序的任务可以由本地控制器执行，研究系统负责生成、分析和改进程序。

知识库中的操作描述应陈述能力；实验记录应保留证据；研究目标和评价方法应单独定义。这样可以保留经验，同时避免让现成流程替代对新问题的思考。

## 四类实验设计

- **物理与光学：** 光源产生信号，经过自由空间、光纤或光芯片传播，与样本相互作用，再采集和分析；通过干预与反馈学习控制量和观测量之间的关系。
- **化学：** 连接试剂转移、搅拌、加热与分析测量，区分控制器设定值与实际体积、温度和反应状态。
- **生物：** 连接视觉评估、样本处理、分装、环境维持与延时成像，保存样本身份、谱系和环境历史。
- **材料：** 连接配方、前驱体制备、加工成型与结构性能表征，让样本制备历史与下一轮设计关联。

完整论述见[实验设计](docs/examples.md)和[论文](paper/manuscript.md)。这些领域设计与仓库已实现的模拟光学示例分别标明。

## 可以立即运行的内容

```bash
python examples/optical_alignment.py --output runs/optical-alignment
python -m unittest discover -s tests -v
```

Python 3.10 及以上即可运行，无运行时第三方依赖。示例包含双轴定位、探测器采集、串并行依赖、反馈搜索和可追溯记录。它输出能力清单、JSONL 实验轨迹与结果摘要，具体模型和扩展方式见[示例说明](examples/README.md)。

## 数据、共享与长期发展

实验轨迹应连接问题、仪器配置、操作、原始观测、分析和决策。这样的记录既支持科学复核，也可以用于设备动力学建模、感知、实验规划、代码改进和仪器设计。学习效果需要在未见过的设备、任务或条件上检验。

跨实验室合作的基础是兼容的能力描述和可理解的证据。不同实验室可以保留自己的仪器特点，通过共享操作、实现与实验知识开展协作。

近期工作从真实仪器的能力清单和适配器开始，逐步验证跨设备迁移、长时间运行、底层实现改进与实验数据的学习价值。具体路线见[研究议程](docs/research-agenda.md)。

本项目希望让研究系统能够在科学问题、实验程序与仪器设计之间持续往返：已有能力足够时开展实验，能力不足时推动仪器本身的进步。
