# IOP · 仪器接入

[English](instrument-setup.md) · [Agent 接入](agent-setup.zh-CN.md) · [驱动](drivers.md) · [型号说明](instruments/README.md)

IOP Runtime 在仪器所在的计算机上持续发现连接、读取身份、保存仪器说明。桌面、浏览器、命令行和 Agent 共用同一份设备信息、平台配置与实验记录。

## 0.8.1 自动完成什么

| 连接或来源 | 自动读取 | 后续处理 |
| --- | --- | --- |
| USB / 串口 | 系统提供的名称、VID/PID、序列号、位置、接口和驱动信息 | 串口与对应的 Windows VISA ASRL 地址归组；相同 USB 标识和序列号的接口互相关联 |
| VISA 仪器资源 | USB、TCPIP、GPIB 的 `INSTR` 地址 | 查询 `*IDN?`，读取制造商、型号、序列号与固件，保存 SCPI 连接 |
| LXI 网络公告 | 本机网络中的 `_lxi`、`_scpi-raw`、`_hislip`、`_vxi-11` 服务 | 使用公告中的 SCPI 控制地址识别；只有网页公告时保留资料并指出缺少控制接口 |
| 已配置的 SCPI | 已保存的 TCP、串口或 VISA 连接 | 通过同一实验调度器读取身份，避免与实验操作交错 |
| 已安装的 NI-DAQmx | 设备型号、序列号、模拟设备标记、模拟/数字/计数器通道 | 保存 SDK 信息；采集操作由对应驱动提供 |
| 已安装的 Basler pypylon | 相机厂商、型号、序列号、完整名称和设备类别 | 保存 SDK 信息；图像采集由对应驱动提供 |
| 已安装的发现扩展 | 扩展返回的身份、接口与仪器说明 | 扩展同时提供驱动配置时自动登记，可用于其他厂商和设备类别 |
| 已配置的软件程序 | 已安装的可执行程序路径 | 复用软件说明中的命令、参数和输出 |

发现工作并行进行。VISA 和厂商 SDK 枚举在独立进程内运行，单个来源超时或不可用不会取消其他来源。默认每 30 秒重新扫描；界面与 Agent 的同时扫描请求共用一次工作。失败的身份查询间隔 60 秒重试，也可手动选择“重新识别”。

## 从身份到可操作的仪器

1. 支持的接口自动读取身份并保存连接，制造商、型号、序列号与固件各自保留来源。
2. 按制造商与型号匹配[型号说明](instruments/README.md)，自动加入操作、参数、单位和资料链接。未知型号保留通用 SCPI `identify`、`query`、`write`，并指出还缺少型号专用操作。
3. 在仪器详情中执行操作、查看返回值、导出说明，或补充型号操作。保存后的信息供所有客户端复用。
4. 已识别仪器在重新建立连接时确认身份。相同型号但序列号不同的仪器不会接替原设备执行实验。
5. 已识别仪器换到新的已发现地址时，使用制造商、型号和有效序列号对应原 ID；只有旧地址本次确实未被其正常工作的发现来源检出、仪器没有待执行或正在运行的操作时，才更新连接。

首次出现和最近一次扫描时间、识别响应、设备 ID、缺失设置、资料来源与发现结果保存到本机。`present=true` 表示本次发现；`false` 表示正常工作的来源本次未发现；`null` 表示尚未确认。保存的网络地址本身不代表当前在线。

## 尚需补充的信息

只有 USB 转串口芯片信息时，Runtime 显示的是接口制造商，不把它作为仪器型号。普通串口还需要实际协议、波特率和结束符；Modbus 寄存器的含义、厂商 SDK 的采集方法由仪器说明或驱动提供。未知串口不会逐个尝试不同协议和波特率。

电缆另一端的模拟电信号、光路、探头与样品关系，需要设备自身的电子说明、现有实验资料或一次人工配置。Agent 从 `lab_context.next_steps` 读取未完成项，复用已知内容，只补充缺少的部分。平台说明保存实际连接、共享资源和初始化过程；这些关系不会由 USB 或串口名称推断。

## 保存型号操作

```sh
iop instrument-profile                      # 查看内置与本地型号说明
iop instrument-profile my-instrument.json   # 保存一个型号说明
iop identify meter --wait                   # 读取已登记仪器的身份
```

型号说明使用明确的制造商与型号匹配，支持额外限定序列号和固件；格式见 [JSON Schema](schema/instrument-profile.schema.json)。已有设备会补入新的操作；原有操作定义保持不变，避免改变已提交实验的含义。修改已有操作时更新设备配置，并在实验结束后重启服务。

## 连续实验与数据

单台设备可直接调用。跨仪器工作流用 `after` 表达先后关系，用 `bindings` 传递结果；反馈循环放在 Python、TypeScript 或其他语言的实验程序中。独立设备并行工作，共享设备和资源按实验配置排队。身份查询使用相同调度机制。

运行编号、参数、操作结果与文件统一保存。关闭界面或 Agent 后，已接受的实验继续执行。图像与波形通过驱动文件输出和流式传输读取，硬件采样与触发由对应驱动处理。
