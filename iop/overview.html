01 / PERSISTENT INSTRUMENT SERVICE

IOP Runtime仪器运行服务

在实验室计算机上持续运行，连接仪器与计算工具，让人和 Agent 通过同一个服务开展实验。

配置设备与实验平台，提交研究程序。服务安排执行、协调资源，持续保存操作、结果与数据。

WindowsmacOSLinuxx86_64 / ARM64
下载与安装 ↗接入 Agent

桌面、浏览器、命令行、MCP 与 SDK 共用服务。

实验方法由程序表达，执行与记录由服务承接。
PERSISTENCE

实验独立持续

已经受理的工作流与实验包在服务端运行。关闭聊天窗口或桌面界面，实验继续执行。

COORDINATION

同一平台共同使用

多个程序共用设备、总线与样品时，由同一个服务安排顺序；独立设备可以并行。

EXTENSION

仪器与算法一起扩展

通过型号说明、驱动、SDK 进程和软件适配器接入新能力，沿用同一套实验接口与记录。

版本依据0.8.3 Release软件说明
02 / ARCHITECTURE

一个服务，多个使用入口

IOP 描述仪器与操作的共同结构；IOP Runtime 将它实现为可安装、持续运行的软件。桌面和网页呈现同一套设备、配置与实验结果。

IMPLEMENTATION

各部分各司其职

Python服务 API、设备驱动、实验调度、配置、命令行与客户端。
Rustiop-execd 管理实验程序、SDK 与命令程序的进程树、进度、取消和退出。
TypeScript供 Agent 产品与应用开发使用的客户端 SDK。
HTML / JS服务提供网页；原生桌面窗口复用相同页面。
SQLite + 文件保存配置版本、实验与操作记录；图像、波形和数据块保存为关联文件。

一台计算机可以管理多个平台

平台分别记录设备、接线、共享对象与初始化方法。同一仪器被多个平台引用时，仍由这一台计算机上的服务统一安排。

多台计算机各自运行服务

上层研究程序可以连接多个 IOP 服务，或用 HTTP 任务适配器接入远端服务。各服务管理自己的资源，跨平台实验顺序由研究程序表达。

03 / PLATFORM SETUP

从连接设备，到可以开展实验

首次接入时，Runtime 提供发现结果与已有说明；Agent 补齐驱动、操作和平台关系。配置保存后重复使用，设备或接线变化时更新对应部分。

1

发现连接与设备身份

读取 USB、串口、VISA、LXI 及 SDK 枚举结果；按适用协议获取制造商、型号、序列号与固件。

Runtime 提供可见连接、身份来源、已匹配的设备与仍需补充的信息。
2

准备驱动与仪器说明

采用匹配的型号说明；安装所需 SDK 或驱动包，定义操作、参数、单位和返回数据。

Agent 根据具体型号补充使用厂商资料与已有适配器，形成可调用的 basic operations。
3

描述实验平台

记录设备、通道、接线、样品和共用控制器；声明总线、设备及其他资源的共享关系。

已有配置优先复用无法从电脑读取的实际接线和样品信息，由 Agent 向使用者确认。
4

执行必要的初始化

将准备步骤保存为可复用过程：设置模式、参考、通道与工作状态，逐项保存执行结果。

由程序明确发起保存配置不触发设备动作；后续根据当前状态决定是否再次初始化。
5

提交实验程序

通过 SDK、MCP 或 API 提交操作、工作流和程序包，读取结果并开始下一轮研究。

Runtime 持续承接连接、调度、进度、记录和文件统一维护，Agent 按需获取变化。
仪器说明回答“能做什么”。
包括操作名称、参数、单位、返回值和对应的驱动方法。发现一个端口，只是获得连接线索；可执行能力来自匹配的说明与驱动。
平台说明回答“如何一起工作”。
接线与共享关系属于平台，先后次序属于本次实验。触发线、设备时钟和触发配置共同决定精确同步。
仪器接入平台配置与初始化平台 JSON Schema
04 / EXECUTION

从基础操作，组合成完整实验

单次操作描述一个能力；可复用过程组织一段方法；研究程序表达循环、条件和反馈。Runtime 按依赖与资源安排它们执行。

结构示意。程序明确写出等待、状态读取与触发步骤；图中的并行关系来自任务依赖与设备能力。

ORDER

顺序与数据依赖

after 指定前序步骤。bindings 将结果传入下一步，同时建立依赖；就绪且资源可用的步骤开始运行。

RESOURCES

共享时保持完整过程

设备默认单操作执行，独立设备可并行。需连续保持实验条件时，对整段实验保留设备、样品等共享资源。

CONTINUITY

运行与会话分离

受理后获得 run_id。程序、事件、结果和文件属于这次实验，客户端重新连接后仍能查询。

中断后，按照已保存的进度继续

程序显式声明 resume

研究程序保存 checkpoint，操作使用稳定 ID。支持续接的程序沿用原实验编号恢复；已完成的调用返回原结果。结果未确定的物理动作先读取状态，再确定下一步。

窗口关闭不影响受理的实验。服务重启后，尚未开始的工作重新排队，执行中的工作保留为中断状态。

恢复一个已声明支持续接的程序
iop resume RUN_ID --request-id continue-1

RUN_ID 替换为原实验编号；程序须已保存恢复所需的进度与数据。

05 / PHYSICAL & DIGITAL OPERATIONS

测量、计算与反馈，进入同一次实验

IOP Runtime 已能接入实体仪器、分析程序、仿真求解器和远端计算任务。它们使用共同的操作、资源和结果结构，可以在一个研究程序中组合。

PHYSICAL

控制与观察真实设备

通用通信SCPI TCP / Serial / VISA；Modbus TCP / RTU。
专有接口Python 驱动、厂商 SDK、独立驱动进程。
具体能力由型号说明表达：通道、参数、单位、状态与操作命令。
DIGITAL

执行计算与软件操作

command每项操作启动可执行程序，传递参数，保存结果、输出与进度。
process保持 SDK 或专用程序进程，通过约定的消息调用操作。
http调用 JSON 接口，或提交、跟踪和取消远端异步任务。
数字操作执行已包含在 IOP Runtime 中。
目前沿用 IOP 的操作和运行接口，仓库没有另行发布独立的 “Digital Operations Protocol / DOP” 规范。
具体工具通过已有编程接口接入。
仿真与分析软件需提供 CLI、SDK 或 HTTP 接口，并配置输入输出、依赖及许可。计算资源数量用于安排任务，线程、显存和 GPU 选择仍由程序设置。
接入一个实际软件，需要准备什么？

安装可执行程序或 SDK，定义操作名称与参数，指定输入、结果文件和进度格式，再声明并发数及资源需求。已有 iop/examples/software/register.py 展示两个计算步骤之间的数据传递与文件保存，可据此连接具体分析工具。数字孪生的模型、参数与实验对应关系由研究程序和领域模型表达。

06 / AGENT INTEGRATION

成为 Agentic Research OS 的实验执行服务

研究系统负责理解目标、生成程序和分析结果；IOP Runtime 持续管理仪器、计算任务与实验数据。产品可以提供统一界面，并让实验服务独立运行。

01 / CONNECT

接入现有接口

MCP 适合 Agent 工具调用；Python / TypeScript SDK 适合研究程序；HTTP API 适合跨语言和远端集成。

02 / UNDERSTAND

读取已有实验平台

先读 lab_context 获得概况和待补充设置；按需读取完整仪器说明，随后通过 cursor 获取变化。

03 / EXECUTE

提交并跟踪实验

提交工作流或程序包，保存返回的 run_id。通过事件、进度和文件接口呈现结果，研究程序决定下一步。

MCP · 生成本机配置
iop mcp-config

将输出中的 command、args 配置到 Agent 的本地 MCP 服务。桥接进程连接或启动本机 IOP；Agent 退出后，已受理的实验继续。

连接另一台实验室计算机

使用 iop --endpoint http://lab-computer:8765 mcp-config，在 Agent 环境配置 IOP_TOKEN。服务监听地址与网络由实验室配置，远端连接使用受控网络或加密连接。

Python · 先读平台信息
from ai4instruments.iop import Client

context = lab.context()
print(context['platforms'])

# 后续按需获取变化。
changes = lab.changes(context['cursor'])

07 / DOWNLOAD & INSTALL

安装在连接仪器的计算机上

0.8.3 提供 Windows、macOS、Linux 的 x86_64 与 ARM64 软件包。核心内置 Python、Rust 执行程序和 Runtime／Agent 依赖；桌面安装另行下载图形依赖。

RELEASE 0.8.3

选择系统与处理器

IOP-0.8.3-windows-x86_64.zip

下载软件包 ↓

适用于 x86_64 的 64 位 Windows。桌面使用 WebView2。

解压后，在软件包目录执行
.\install-desktop.ps1

安装完成后，从系统应用菜单打开 IOP Runtime。

首次启动

使用安装器提供的 iop 命令
iop init
iop start
iop open

浏览器使用 iop open；桌面使用 iop desktop。两者连接或启动同一个服务，关闭窗口后服务继续运行。

若终端找不到 iop，使用安装完成时显示的命令路径。

Agent 使用运行 iop mcp-config，将生成的配置加入 Agent。
建立平台查看发现结果，补充所需驱动和实际接线，执行必要的初始化。
更新版本完成当前实验，iop stop 后运行新版安装器；默认 ~/.iop 配置与记录保留。

08 / VERSION & ENGINEERING

0.8.3：共享连接与型号说明的扩展

发布于 2026 年 10 月 25 日。核心、客户端、桌面和浏览器沿用同一个版本；本页内容对应正式发行代码。

01

同一总线上的多台仪器

Modbus 仪器共用连接，按各自站号和响应超时执行。修改空闲仪器的说明不关闭其他仪器正在使用的连接；不同总线可并行。

02

可单独安装的型号说明包

从包内 JSON 读取 SCPI 型号与操作说明，不需启动 SDK。记录来源和包版本；本地说明、安装包、内置说明依次匹配。

03

按需查找、预览与采用

CLI、SDK、HTTP 和 MCP 均支持筛选及分页。界面可预览命令、单位与资料，采用时保留已有操作并保存配置版本。

当前可以直接复用的能力

常驻服务、桌面与网页、通用驱动适配器、平台配置、串并行调度、共享资源、实验程序包、MCP 与 SDK、配置版本、checkpoint 续接，以及二进制分块数据。

持续实验、分块数据与内置 Python 的发行包已在 0.8.2 提供，0.8.3 继续沿用。

仪器生态的当前覆盖

内置 SCPI 型号说明覆盖 SR830 与 RIGOL DP800 系列，共 9 个型号的部分操作。NI-DAQmx、Basler pypylon 提供设备枚举入口；操作能力仍取决于相应驱动。

跨系统安装、软件通信与界面已进入发行流程检查。型号说明尚未在本开发环境的真实仪器上验证，后续需要实验室补充具体型号与长期运行记录。
