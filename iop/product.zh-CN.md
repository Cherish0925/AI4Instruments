# IOP Runtime · 软件与平台

[English](product.md) · [下载](https://github.com/Cherish0925/AI4Instruments/releases/latest) · [安装](interface.zh-CN.md) · [Agent 接入](agent-setup.zh-CN.md)

IOP Runtime 是安装在仪器计算机上的常驻软件。它维护仪器连接、执行实验、协调设备使用并保存过程与数据。桌面、网页、命令行和 Agent 连接同一个服务。

## 使用入口

| 入口 | 当前实现 | 适合的工作 |
| --- | --- | --- |
| Desktop | 独立窗口、系统应用菜单入口 | 配置平台、查看设备、操作与结果 |
| Web | 服务提供的浏览器界面 | 在本机或可访问服务的电脑上操作 |
| CLI | `iop` 命令 | 安装、自启动、配置、提交与查询实验 |
| Python / TypeScript | 客户端库 | 编写实验程序、反馈循环与数据处理 |
| HTTP API | `/v1/*` | 任意语言、其他软件和远端 Agent 集成 |
| MCP | `iop mcp`，标准输入输出连接 | Agent 读取实验室信息、配置平台和执行实验 |
| 无界面运行 | `iop serve` 或系统自启动 | 服务器和长期实验 |

IDE 内的 Agent 可以通过 MCP、SDK 或 CLI 使用 IOP；当前没有单独的 IOP IDE 扩展。网页由实验室自己的服务提供，项目没有托管云账户或云服务。

## 系统与发行包

| 系统 | 架构 | 发行包与运行要求 |
| --- | --- | --- |
| Windows | x86_64、ARM64 | ZIP 与 PowerShell 安装脚本；桌面使用 WebView2。ARM64 桌面所需的 .NET 由安装脚本安装。 |
| macOS | ARM64、x86_64 | ZIP 与安装脚本；当前构建目标分别为 macOS 14+、15+；安装后创建应用入口。 |
| Linux | x86_64、ARM64 | ZIP 与安装脚本；运行服务面向 glibc 2.35+。桌面需要图形会话与 Qt 依赖；ARM64 桌面需要 glibc 2.39+。 |
| WSL | 对应 Linux 架构 | 使用 Linux 服务与浏览器入口；仪器需要已被宿主机转接到 WSL。Windows 专用 SDK 在 Windows 服务中运行。 |

发行包包含 Python、对应架构的 Rust 执行程序和 Runtime／Agent 依赖，核心可离线安装。桌面安装脚本另外下载图形依赖。当前发行形式为 ZIP 与安装脚本；Windows 签名、macOS 公证及自动更新尚未提供。

版本更新：结束当前实验，用旧安装的 `iop stop` 停止服务，再运行新版本安装脚本。默认数据目录 `~/.iop` 中的配置与实验记录继续保留。

## Runtime、Agent 与人的分工

| 工作 | 负责方 | 什么时候需要做 |
| --- | --- | --- |
| 服务启动、设备连接、操作排队、串并行安排、记录与文件 | Runtime | 持续自动运行 |
| 读取已有仪器说明、平台拓扑、操作参数与历史结果 | Agent 或实验程序 | 接入时读取，配置有变化时更新 |
| 读取身份并匹配已有型号操作 | Runtime | 首次连接与重新发现 |
| 补充未知协议与型号操作 | Agent 或人，使用厂商资料 | 发现结果提示需要补充时 |
| 指明实际接线、样品、共用对象与实验目的 | 已有平台配置；缺少时由 Agent 向人询问 | 首次搭建或物理布置改变时 |
| 设计实验、定义步骤依赖、分析结果、决定下一次实验 | Agent 或人 | 随研究任务进行 |

平台保存后直接复用。保存说明不执行设备动作；初始化是一个有名称、有记录的实验过程。Agent 先读取已有过程，再决定是否运行，不必每次连接都重新初始化。

## 已完成与继续建设的部分

0.8.2 已提供统一服务、以上使用入口、通用适配器、平台配置、实验调度、记录与文件、MCP 接入和实验室信息接口。发布流程在原生系统上构建软件包，并检查真实安装、浏览器、桌面窗口和 Agent 通信。

后续产品工作包括独立安装器、签名与公证、自动更新、大规模型号与驱动目录，以及跨实验室的长期实机运行。已有通用适配器可以连接符合相应协议的设备；型号专有命令、SDK 和操作说明仍需要相应实现。

## 持续运行与访问

本机使用时自动读取本机连接信息，不增加逐步确认窗口。远端访问沿用同一个服务令牌；实验程序使用服务账户的权限执行，远程网络使用实验室现有的受控网络或加密连接。

客户端或窗口关闭后，已经受理的实验继续。服务重启后恢复排队任务，将此前执行中的任务记录为中断。声明支持续接的程序可以沿用原实验编号，[从保存的进度继续](continuity.zh-CN.md#程序保存与续接)；存在结果不明的物理动作时，先读取设备状态并记录处理结果。同一设备与共享资源按已保存的配置安排，独立设备可以并行工作。
